# 功能二：AI 自动下发配置（MCP 服务）

## 这个功能是干什么的？

拓扑在 eNSP 里启动之后，**不用你一台一台敲命令**。AI 通过 MCP 服务直接连进每台设备的命令行，帮你：

- 探查设备（型号、版本、已有配置）
- 下发你设计的配置（OSPF、VLAN、NAT、ACL……）
- 跑校验（路由表对不对、ping 通不通）
- 保存配置、生成实验报告

一句话流程：**你说"给 R1 配 OSPF"，AI 就配好并验证给你看。**

> 和功能一的关系：功能一生成"图纸"（.topo），本功能负责"施工"（配置）。两个功能独立可用，搭配用最顺。

---

## 安装（三分钟）

前置：Windows 10/11、已安装华为 eNSP。

### 方式 A：WorkBuddy 用户（一键）

```bat
双击仓库根目录的 install.bat
```

它会自动：建虚拟环境 → 装包 → 应用补丁 → 注册到 WorkBuddy 的 MCP 配置。装完后在 WorkBuddy「连接器」页面找到 `grbj-ensp`，点一次「信任」即可。

### 方式 B：其他 AI 工具（Claude Code / Cline 等）

```bat
:: 1. 在仓库根目录建虚拟环境并安装
python -m venv .venv
.venv\Scripts\pip install grbj_ensp_mcp-0.2.2-py3-none-any.whl

:: 2. 关键一步：用补丁版覆盖（wheel 不含补丁！）
copy /y src\grbj_ensp_mcp\topo_builder.py .venv\Lib\site-packages\grbj_ensp_mcp\topo_builder.py
```

然后在你的 AI 工具的 MCP 配置文件里加一段（`command` 改成你实际的 .venv 路径）：

```json
{
  "mcpServers": {
    "grbj-ensp": {
      "command": "C:\\你的路径\\.venv\\Scripts\\python.exe",
      "args": ["-m", "grbj_ensp_mcp.server"]
    }
  }
}
```

### 验证装好了没

```bat
.venv\Scripts\python scripts\check_health.py
```

8 项全 PASS 即可（详见[功能三](../功能3-自检与排错/使用说明.md)）。

## 日常怎么用（六步闭环）

```
① 你：在 eNSP 打开 .topo，启动设备（指示灯变绿）   ← 只能人工，AI 碰不到 GUI
② 你：对 AI 说："拓扑已启动，拓扑文件在 xxx.topo，开始配置"
③ AI：解析拓扑 → 自动扫描 Telnet 端口（127.0.0.1:2000+）连上每台设备
④ AI：探查 → 下发配置 → 跑校验（路由表/ping）→ save
⑤ AI：给你一份总结报告
⑥ 循环：下一批设备，回到第 ① 步
```

**只有第 ① 步和第 ② 步需要你动手，其余全自动。**

实用提示：

- 设备多时**分批启动**（先出口区、再核心、再接入），32 台全开可能吃掉 8~12 GB 内存
- 对 AI 报接口名要写**全称**：`GigabitEthernet0/0/1`、`LoopBack0`，eNSP 不认缩写
- 配置错了直接把报错贴给 AI，它自带 15 类 VRP 错误知识库做根因诊断

## 常见问题

| 现象 | 原因与解决 |
|---|---|
| AI 说"扫不到设备" | 设备没启动（eNSP 里指示灯没变绿），或 eNSP 没开。启动设备后重试 |
| 连接器里看不到 grbj-ensp | install.bat 装完后需要在连接器页点「信任」；确认配置写进了 `%USERPROFILE%\.workbuddy\mcp.json`（本仓库已修正路径，上游包写错位置） |
| 配置下发一半断了 | eNSP Telnet 有 5 分钟空闲超时，长时间人工操作后再下发，让 AI 重新建连即可 |
| 配完不生效 | 检查是否忘了 `save`；让 AI 跑一遍校验（display 路由表/ping）定位 |
