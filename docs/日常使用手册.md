# grbj-ensp-mcp (enhanced) 日常使用手册

> 工具链组成：MCP 服务（`grbj-ensp`，31 个工具）+ 两个 Skill（拓扑生成 / 配置方法论）+ 自检脚本
> 适用平台：Windows + 华为 eNSP（eNSP 本体需自备）
> 本手册为仓库通用版；按 WorkBuddy 规范安装时路径均可直接使用。

---

## 一、先记住这一张图：三个环节各管一段

| 环节 | 靠什么 | 谁主导 | 需要 MCP 启用吗 |
|---|---|---|---|
| **生成 / 修改 .topo** | 本地 Python 调 `NativeTopoBuilder` 库 | 你说需求，AI 生成 | 不需要 |
| **打开 + 启动设备** | eNSP GUI | **只能你来** | — |
| **配置下发 + 校验** | MCP 工具（31 个） | AI | 需要 |
| **实验记录 / 报告** | `skill/grbj-ensp-smart-config` 方法论 | AI | 不需要 |

一句话：**生成靠脚本调库，配置靠 MCP，写报告靠技能**——三段各司其职，别混。

## 二、开工前 10 秒自检（推荐养成习惯）

```bash
python scripts/check_health.py
```

看到 `工具链健康，可以开工。` 就没问题。它检查：解释器与包导入、USG6000V/S3700 补丁是否生效、仓库 src 与运行环境是否一致、MCP 注册状态、技能在位、端到端能否真渲染出拓扑，顺带告诉你 eNSP 有没有在跑。

**什么时候必须跑**：① 新机器装完 ② 升级过 wheel ③ 报奇怪的错之前 ④ 很久没用之后。

## 三、场景 A：生成一个新拓扑（最高频）

### 你怎么说

把「设备 + 连线」讲清楚就行，格式随意：

```
生成一个拓扑：
- 设备：AR2220×2（R1、R2）、S5700×1（SW1）、PC×2
- 连线：R1 GE0/0/0 ↔ SW1 GE0/0/1，R2 GE0/0/0 ↔ SW1 GE0/0/2，
       PC1 ↔ SW1 GE0/0/3，PC2 ↔ SW1 GE0/0/4
```

也可以只说大意让 AI 规划接口：「两台 AR 做双出口互备，下面一台交换机接几台 PC」。

中文设备名直接写（`SW-ACC-直播`），编码问题已在生成脚本里封死。

### 生成器会做什么

1. 自动做型号 → XML index 换算（AR 0 起 / USG6000V 枚举式 / S5700 偏移 +1 / S3700 22E+2GE）
2. 落盘三要素：`encoding="UNICODE"` 声明 + CRLF + **GBK**（UTF-8 必乱码——eNSP 是老 Win32 程序）
3. 自检：设备数 / 连线数 / 中文 GBK 无损，逐条回读
4. 交付 `.topo` + 校验清单

参考实现：`skill/ensp-topo-generate/scripts/gen_topo_template.py`（可直接改数据复用）。

### 你要做的

在 eNSP 里打开 → 核对渲染和连线 → 点启动。

> **接口名别让 AI 猜**：型号默认口序它懂，但哪根线接哪个口是你的设计意图，最好明说或让它给一版规划确认。

## 四、场景 B：设备启动后下发配置（MCP 主场）

### 前提

1. eNSP 已打开 `.topo`，设备已**点启动**（指示灯变绿）
2. AI 工具的连接器/扩展页里 `grbj-ensp` 已启用信任

### 你怎么说

```
拓扑已启动，文件在 xxx.topo，按实验步骤下发配置
```

更简单的也行：「拓扑启动了，帮我配出口区那 6 台」。

### AI 会做什么

```
ensp_load_topology    解析 .topo，拿到设备/连线/Telnet 端口（2000+）
     ↓
扫描建连              逐台 Telnet 上去
     ↓
逐台探查              型号 / 版本 / 现有配置（先看再配，避免覆盖）
     ↓
ensp_send_commands    批量下发命令
     ↓
校验                  display ip routing-table / OSPF / VLAN / ping
     ↓
ensp_save_config      save
     ↓
交付总结报告
```

配错了会自动走 `ensp_diagnose_error`（内置 VRP 错误知识库）定位根因。

### 三条铁律

| 铁律 | 原因 |
|---|---|
| **设备必须先启动** | MCP 只能在设备启动后经 127.0.0.1:2000+ Telnet 连入 |
| **分批启动，别全开** | 大拓扑全并行内存压力大（每台 USG6000V 约占 1 GB） |
| **接口写全称** | `GigabitEthernet0/0/1`、`LoopBack0`——eNSP 不认缩写 |

## 五、场景 C：改一个已有拓扑

| 你想干什么 | 你怎么说 |
|---|---|
| 加设备 / 加连线 | 「在 xxx.topo 里加两台 PC 接到 SW1 的 GE0/0/5、GE0/0/6」 |
| 核查生成对不对 | 「把 xxx.topo 的设备和连线全列出来给我校验」 |
| 重排布局 | 「xxx.topo 布局太乱，重新排一下坐标」 |
| 推演变体 | 「按某个已有拓扑加一个终端再生成一版」 |

改已有拓扑建议**改生成脚本重跑**而不是手改 XML——脚本是唯一权威口径源，重跑不会漏字段。

## 六、场景 D：出问题了

| 现象 | 先说这句 | AI 怎么办 |
|---|---|---|
| 配置下发后不通 | 「xxx 配完 ping 不通，报错是 ……」 | 走诊断流程：抓配置 → 比对预期 → 定位 |
| 命令被拒 | 「下发 xxx 命令报错 ……」 | 查 VRP 错误知识库给根因 |
| 拓扑连线疑似不对 | 「xxx.topo 的连线核对一下」 | LLDP 实测 × 设计图交叉比对 |
| 中文乱码 | 「拓扑中文乱码了」 | 编码问题，重生成（GBK 落盘已固化） |
| 生成失败 / ModuleNotFound | 先跑 `check_health.py` | 大概率补丁被升级覆盖，按提示恢复 |

| 事项 | 谁 |
|---|---|

| 技术方案判断与结论 | 你（AI 只做辅助，学术场景请遵守所在机构规范） |

## 九、维护速查（升级时才需要）

**核心原则：运行环境（venv/site-packages）管「跑什么」，仓库管「补丁丢不了」。**

**升级上游新版的四步**：
1. 下载新 zip 解压，对比 `src/grbj_ensp_mcp/` 与本仓库 `src/` 的差异
2. venv 里 `pip install --upgrade <新 wheel>`
3. **重打补丁**：若上游未合并 USG6000V 支持，用本仓库 `src/grbj_ensp_mcp/topo_builder.py` 覆盖 site-packages 同名文件（上游若改过该文件，需合并不是盲覆盖）
4. 跑 `python scripts/check_health.py`，全绿即完成

**验证补丁**：`python tests/verify_usg6000v.py`（免安装，直接用仓库 src）。
