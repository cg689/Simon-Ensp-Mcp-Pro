# 功能三：自检与排错

## 这个功能是干什么的？

两个现成脚本，回答你两个最常见的问题：

- **"我这环境装对了吗？"** → `scripts/check_health.py`，8 项体检一次全查
- **"USG6000V 的补丁还在吗？"** → `tests/verify_usg6000v.py`，专门验证补丁没丢

**什么时候跑**：刚装完、换电脑、升级过后、报了看不懂的错误之前。两个脚本都**零配置**，克隆仓库后直接跑。

---

## 用法

### 1. 环境体检（8 项全查）

```bat
:: 已装到 venv 的：
.venv\Scripts\python scripts\check_health.py

:: 或者用任意 Python（脚本会自动找到已安装的环境）：
python scripts\check_health.py
```

检查内容：venv 存在、包能导入、**USG6000V 补丁生效**、**S3700 接口表修正生效**、补丁源码与运行版一致、MCP 已注册、技能在位、端到端渲染（现场生成一个含 USG6000V 的最小拓扑）。

全部 `[PASS]` 就可以放心开工。

### 2. 补丁专项验证

```bat
python tests\verify_usg6000v.py
```

不需要安装任何包（直接读仓库 `src/`），验证补丁本体 + 生成的拓扑文件格式（GBK 编码、UNICODE 声明、CRLF 换行）+ 回读解析。

## 报错了先查这张表

| 报错/现象 | 大概率原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: grbj_ensp_mcp` | 包没装，或跑脚本的 Python 不是 venv 里的 | 用 `.venv\Scripts\python.exe` 跑；或先完成[功能二安装](../功能2-配置下发/使用说明.md) |
| 体检第 3/4 项 FAIL（补丁缺失） | 重装/升级过 wheel，补丁被官方版覆盖 | 重新执行覆盖：`copy /y src\grbj_ensp_mcp\topo_builder.py .venv\Lib\site-packages\grbj_ensp_mcp\topo_builder.py` |
| 体检第 6 项 FAIL（MCP 未注册） | 没跑 install.bat 或手动注册 | 见[功能二](../功能2-配置下发/使用说明.md)安装一节 |
| eNSP 打开 .topo 中文乱码 | 生成脚本用 UTF-8 落盘 | **必须 GBK**：照抄[功能一模板](../功能1-生成拓扑/使用说明.md)的落盘写法 |
| AI 扫不到任何设备 | 设备没启动 / eNSP 没开 | eNSP 里启动设备（指示灯变绿）后重试 |
| AI 下发配置报接口不存在 | 接口名用了缩写 | 写全称：`GigabitEthernet0/0/1`、`LoopBack0` |
| 生成的拓扑 eNSP 打不开 | 文件格式三要素缺一 | 交给本仓库 builder 生成就不会出；自写的检查：GBK 编码 + `encoding="UNICODE"` 声明 + CRLF 换行 |

## 亲手改过代码之后

改了 `src/` 下任何源码，跑一遍两个脚本确认没改坏；改了 `topo_builder.py` 额外跑：

```bat
python -m pytest tests\ -x
```

上游自带的测试套件全绿即可提交。
